# Sprint 6 Checklist

Источник: [`sprint-6-plan.md`](sprint-6-plan.md).

## 1) Снимок

- [x] Снимок собирается из базы, окно формулы не вызывает.
  Примечание: `assemble_snapshot` читает факт, группу, ставки и отметки. Спецнадбавка берётся по региону точки. Окно `month_charges`, `transition_charges` и `year_end_reimbursement` не вызывает. Прогон не пишется.
- [x] Закрытие вызывает `month_charges`, `transition_charges` или `year_end_reimbursement` по отметке загрузки и само момент перехода не ищет.
  Примечание: `close_month`. Нет отметки — `month_charges` по группе справочника, даже если объём уже в другой группе. У точки с несколькими договорами каждый договор округляется отдельно, в строку точки попадает сумма. `cheaper` — `transition_charges`, прошлый месяц в строки не входит. `dearer` — `year_end_reimbursement`. `group_of` снимок не вызывает.
- [x] Население не попадает в снимок и видно в готовности.
  Примечание: карточка `population` в точки снимка не входит. Готовность показывает число таких потребителей. Нет спецнадбавки статус `ready` не снимает.
- [x] Ставка берётся на 1-е число. Дата не с 1-го в базе не встречается.
  Примечание: январь берёт тариф с 1 января, октябрь — с 1 октября. Запись на 15-е отклоняется, в `tariff` дней кроме 01 нет.
- [x] Входящий остаток не восстанавливает предыдущие месяцы.
  Примечание: остаток на март виден в снимке. Месяцев до него нет. Факт апреля при закрытии июня считается, январь–март из остатка не возникают. У месяца только с остатком нет цифры сверхлимита — потребитель в готовности.

## 2) Экран загрузки

Прогон на январских файлах без этого экрана не проверяется.

- [x] Годовой план загружается из файла, выбранного в окне. Прогон не создаётся.
  Примечание: окно «Загрузка данных», вкладка «План». Кнопка открывает файл и вызывает `load_annual_plan`. Итог загрузки остаётся на экране, строки плана видны в таблице. Прогона после загрузки нет. Справочники — отдельное окно, регионы в нём последние.
- [x] Расхождение группы плана показано списком и акцептуется группой файла или расчётной.
  Примечание: по точке и году одна строка. Список предлагает группу файла и расчётную, иную не предлагает. Повторная загрузка того же плана решение сохраняет.
- [x] Факт месяца загружается из файла. Расхождения видны и карточек не создают.
  Примечание: неизвестный покупатель даёт `new_consumer`, `new_contract` и `new_point`. Потребитель и точка в справочнике не появляются.
- [x] Повторная загрузка не удаляет уже записанный прогон.
  Примечание: вторая загрузка плана оставляет одну строку `run`.

## 3) Допсоглашение

Своя вкладка. Справочники те же карточки умеют по одной; здесь один документ собирает связанные правки. Файл допсоглашения не разбирается. Полноценный ввод января ждёт эту вкладку: документ не сводится к изменению объёма.

- [x] Новый покупатель, его договор и точка получают объёмы года и группу на 1 января.
  Примечание: вкладка «Допсоглашения», документ «Новый покупатель». Код назначает программа. Объём пишется в `annual_plan`, группа на 1 января — по сумме. Группа вкладки, отличная от суммы, открывает `group_mismatch` и акцептуется группой вкладки или расчётной. Месячные объёмы не пишутся. Прогон не создаётся.
- [x] Новый договор и точка известного покупателя получают объёмы и группу.
  Примечание: покупатель остаётся один, код прежний. Новый договор и точка получают объём и группу на 1 января. Уже известный код точки вторую карточку не создаёт и не отклоняется: объём нового договора пишется отдельно, карточка остаётся на первом договоре.
- [x] Новая точка известного договора получает объёмы и группу.
  Примечание: прежняя точка остаётся. Новая получает объём и группу на 1 января.
- [x] Переименование покупателя оставляет его код.
  Примечание: номер договора показывает прежнее имя, новое вводится отдельно. Код тот же. Строка документа хранит сумму годовых объёмов договора: до и после равны. Переименование точки меняет адрес и оставляет код.
- [x] Перенос точки к другому покупателю оставляет одну точку: номер не копируется.
  Примечание: запись точки одна, код тот же, договор другой. Объём прежнего договора в `annual_plan` остаётся, новый договор получает свой. Группа на 1 января — по сумме обоих.
- [x] Изменение объёма года существующей точки пересчитывает группу на 1 января.
  Примечание: объём года переписывается, группа на 1 января считается заново по сумме объёмов точки.
- [x] Строка документа хранит дату и объёмы до и после. В стоимость месяца она не входит. Прогон не создаётся.
  Примечание: `amendment` хранит договор, дату, код точки и объёмы до и после. У переименования покупателя кода точки нет. `close_month` эту строку не читает, стоимость месяца не меняется. Вкладка прогон не создаёт.

## 4) Прогон

- [x] Успешное закрытие пишет один прогон со статусом «готов».
  Примечание: `close_month` при готовности пишет одну строку `run` со статусом `ready` и строки `result_line` с января по этот месяц. Январь группы 5 хранит 46 030,30.
- [x] Пробел тарифа не подставляет ставку.
  Примечание: нет тарифа — готовность `blocked`, суммы пустые, прогон не пишется.
- [x] Повторное закрытие заменяет прогон и не оставляет второй.
  Примечание: два закрытия января оставляют одну строку `run` и одну строку результата.
- [x] Прогоны других месяцев на месте.
  Примечание: после закрытия февраля прогон января остаётся. Вместе два прогона и три строки.
- [x] Закрытие месяца не меняет прогоны предыдущих месяцев.
  Примечание: январская строка после закрытия февраля по-прежнему 46 030,30. Ставку, которую январь уже выбрал, заменить нельзя. Ставка с 1 октября записывается.
- [x] Заблокированная попытка не удаляет уже записанный прогон.
  Примечание: закрытие без тарифа оставляет прежний прогон, его статус и признак НДС.

## 5) Экран расчёта

- [x] Выбор года, месяца и НДС.
  Примечание: окно «Расчёты». Год, месяц и флаг «НДС, %». Ставка вводится в процентах, в прогон пишется доля. Без тарифа кнопка «Рассчитать» неактивна. Неверная ставка прогон не пишет. Повтор того же периода ждёт подтверждения.
- [x] Таблица с фильтром региона, группы и потребителя.
  Примечание: строки закрытого месяца на вкладке «Результаты». Регион и группа — списки. Потребитель ищется по фрагменту кода или имени. Населения в таблице нет. На вкладке «Расчёт» удачный расчёт подписан, строки без ставки перечислены и успехом не считаются. Там же суммы по группам и покупатели, сменившие группу.
- [x] Карточка со следом и переходным тарифом.
  Примечание: группа на начало, смена, объём отнесения, план, факт, ставка, коэффициент, база, сверхлимит, спецнадбавка. У перехода — тариф и след: поправка, ставка новой группы, база.
- [x] Итог потребителя за месяц и с января.
  Примечание: сумма уже округлённых строк его точек на вкладке «Результаты». Февраль с тем же объёмом, что январь: за месяц 46 030,30, с января 92 060,60. Сумма всех групп — на вкладке «Расчёт».
- [x] Расчёт не блокирует окно.
  Примечание: закрытие идёт отдельным соединением вне потока окна. Пока оно считается, окно меняет заголовок. По завершении таблица перечитывается.
