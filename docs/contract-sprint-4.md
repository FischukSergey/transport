# Контракт Sprint 4

Источник: [`sprint-4-plan.md`](sprint-4-plan.md), [`../архитектура.md`](../архитектура.md) «Модель данных».

## 1) Решения спринта

- Один файл SQLite на программу.
- Пустой файл при открытии получает схему этого контракта.
- Запись идёт в текущие строки. История версий справочника не ведётся.

## 2) Таблицы

Обязательные поля:

- регион: код, наименование;
- потребитель: код, наименование, регион, тип (`industrial`, `communal`, `population`);
- точка: потребитель, код, признак нераздельного учёта;
- договор: точка, метод, даты услуг, годовой объём, запрет корректировки группы, новый потребитель, разовые работы, объём следующего года;
- допсоглашение: договор, дата, объём до, объём после;
- план месяца: точка, год, месяц, объём;
- тариф: группа, дата начала, ставка без НДС;
- спецнадбавка: регион, группа, дата начала, ставка без НДС;
- подтверждение ставки: месяц, ссылка на ставку.

Группа тарифа и спецнадбавки: `1a`, `1` … `7`. Значение `8` и тип `population` для спецнадбавки отклоняются.

Таблицы факта, прогона, строки результата и замечания создаются пустыми. Их запись — спринты 5, 6 и 8.

## 3) Ставка месяца

На месяц берётся ставка с наибольшей датой начала, которая не позже 1-го числа месяца, в той же группе. Для спецнадбавки дополнительно совпадает регион.

Если выбранная ставка начинается не в первый день месяца, месяц считается неподтверждённым, пока нет записи подтверждения.

## 4) Экраны

Справочники и ставки доступны из окна. Расчёта, импорта и отчётов на этих экранах нет.

## 5) Совместимость

Снимок движка не читает базу сам. Прикладной слой соберёт его в спринте 6 из этих таблиц, не меняя поля [`contract-sprint-3.md`](contract-sprint-3.md).
