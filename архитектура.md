# Архитектура проекта

Документ описывает устройство программы расчёта стоимости транспортировки газа. Границы предметной области заданы в `концепция.md`. Здесь — слои, данные, зависимости и сборка.

## Ограничения

- Локальное приложение для Windows. Серверной части нет.
- Данные лежат в одном файле SQLite рядом с программой.
- Интерфейс — PySide6.
- Разработка на Mac, тот же исходный код. Исполняемый файл для Windows собирается на GitHub Actions.
- На Windows Docker не используется. На Mac при разработке Docker допустим.
- Язык реализации — Python.
- Деньги и объёмы считаются в `Decimal`. Дробный тариф и копейки не проходят через двоичную плавающую точку.

## Слои

Зависимости направлены внутрь: интерфейс и база знают о прикладном слое, прикладной слой знает о движке, движок не знает ни о ком.

```text
ui            экраны, таблицы, фильтры, диалоги
    ↓
application   сценарии: импорт, проверка, прогон, отчёты
    ↓
domain        группы, объём месяца, стоимость, спецнадбавка по группе
ingest        разбор CSV и XLS, сопоставление колонок
quality       структурные, связные и предметные проверки, аномалии

storage       SQLite, репозитории, один прогон на месяц
```

`domain`, `ingest` и `quality` не импортируют `ui` и `storage`. Одинаковый вызов движка из теста и из интерфейса даёт один результат.

Прикладной слой собирает вход из базы, вызывает чистые функции и записывает результат. Экран не вызывает формулы напрямую и не пишет SQL.

## Каталог исходников

```text
src/transport/
  domain/         группы, формулы стоимости и перехода, стоимость месяца
  application/    сценарии и сборка входа для движка
  ingest/         CSV, XLS, профили колонок
  quality/        ошибки, несоответствия, аномалии
  storage/        схема SQLite и репозитории
  ui/             окна PySide6
tests/
  domain/         эталонные кейсы методики
  ingest/
  quality/
.github/workflows/
```

Код групп и формул приказа живёт только в `domain`. Отчёты читают уже посчитанные строки и ничего в них не пересчитывают своим способом.

## Поток данных

```text
файл CSV или XLS
    → ingest: таблица строк и профиль колонок
    → quality: замечания, без записи в факт
    → подтверждение пользователя
    → storage: справочники, план, факт, тарифы
    → application: снимок входа на период
    → domain: строки результата и след
    → storage: единственный прогон месяца, строки, замечания пробелов
    → ui: таблица, карточка, план-факт, статистика
```

Загрузка файла не запускает расчёт. Расчёт не меняет исходные объёмы и ставки.

## Движок

Движок принимает уже собранный снимок и возвращает результат. В снимке на каждую расчётную точку:

- потребитель и признак типа;
- регион;
- группа точки из таблицы;
- договор: срок, запрет корректировки группы, новый потребитель, разовые работы; плата всегда от факта;
- объём месяца, уже включающий сверхлимит, и два объёма сверхлимита с коэффициентами 1,1 и 1,5;
- годовой план в месячный снимок не входит: группа уже записана в таблицу;
- ставки групп по месяцам, включая группу 1а;
- спецнадбавка по региону и группе месяца;
- ставки переходящих потребителей, если они есть в решении;
- включён ли НДС и его ставка.

Потребитель с типом «население» в снимок расчёта не входит. Прикладной слой отсекает его до вызова движка и оставляет замечание в журнале.

На выходе по точке и месяцу: группа на начало месяца, группа после проверки, объёмы, коэффициент сверхлимита, применённый тариф, база, сверхлимит, спецнадбавка, НДС при запросе, текст следа. След хранит объём отнесения, границы группы, ставку месяца и формулу перехода, если группа сменилась.

Движок ведёт накопители с 1 января по точку: факт с начала года и несогласованный сверхлимит. Точки одного потребителя складываются только в итоговой стоимости. Для группы их объёмы суммируются лишь когда учёт точки не разделяет.

Если на месяц и группу нет ставки транспортировки, движок не заполняет стоимость этой строки и возвращает пробел. Месяц остаётся незакрытым. Нет ставки спецнадбавки для региона и группы обнуляет только строку спецнадбавки.

Сверхлимит движок не выделяет из суточных данных и не делит месяц на половины. По точке он получает объём, в котором сверхлимит уже сидит, и два объёма с коэффициентами 1,1 и 1,5. База месяца — объём минус оба этих объёма. Для коммунально-бытовых оба объёма идут с коэффициентом 1.

## Модель данных

Один файл SQLite. Повторная загрузка обновляет текущие данные периода. Закрытие месяца записывает один прогон этого месяца и заменяет предыдущий расчёт того же месяца. История прогонов не хранится.

### Справочники

| Сущность | Поля |
|---|---|
| Регион | код, наименование |
| Потребитель | код, наименование, регион, тип: промышленный, коммунально-бытовой, население |
| Расчётная точка | потребитель, код точки, признак «учёт не разделяет физические точки» |
| Договор | точка, дата начала и окончания услуг, годовой объём, число полных месяцев, запрет корректировки группы, новый потребитель, разовые работы, годовой объём договора на следующий год |
| Допсоглашение | договор, дата, объём до и после, запрет пересчёта месячных объёмов |
| Годовой план | точка, год, объём. По нему назначается группа этого года |
| Группа точки | точка, год, группа |
| Решение по тарифу | организация, год, дата начала действия |

В эксплуатации ожидаются два региона. Число регионов в схеме не зашито: регион — строка справочника.

Тип «население» хранится, чтобы исключение было видно в журнале и в карточке. Расчётных строк у такого потребителя нет, ставка спецнадбавки для него не заводится.

Группы 1а и 1–7 — код движка, не редактируемый справочник. Группа 1а есть всегда. Ставки переходящих потребителей, если они заданы в решении, относятся к тарифному решению.

### Ставки

| Сущность | Поля |
|---|---|
| Тариф транспортировки | решение, группа, дата начала, ставка без НДС за 1000 м³ |
| Спецнадбавка | регион, группа транспортировки, дата начала, ставка без НДС за 1000 м³ |

Для населения строка спецнадбавки не создаётся. Интервал ставки действует от своей даты до следующей даты той же группы транспортировки в том же регионе. На календарный месяц берётся ставка, действующая на 1-е число, по группе, применённой в этом месяце. Если дата начала не первое число, прикладной слой не закрывает месяц, пока пользователь не подтвердит применение. Подтверждение хранится отдельной записью: месяц, ставка, пользовательское решение.

### Факт

| Сущность | Поля |
|---|---|
| Месячный факт | точка, год, месяц, объём включая сверхлимит, сверхлимит с коэффициентом 1,1, сверхлимит с коэффициентом 1,5, тип промышленный или коммунально-бытовой, вид строки: месяц или входящий остаток |

Первая загрузка года — либо набор месяцев с января, либо один входящий остаток на конец указанного месяца. Остаток не раскладывается на месяцы. Месяцы до него в расчёте группы и тарифа не восстанавливаются.

### Прогон и качество

| Сущность | Поля |
|---|---|
| Загрузка | файл, тип данных, момент, профиль колонок, статус приёмки |
| Замечание | загрузка или прогон, серьёзность, код правила, сущность, ссылка на строку файла, текст |
| Прогон | год, месяц, статус, включён ли НДС. На пару год и месяц приходится одна запись |
| Строка результата | прогон, точка, месяц, группа, объёмы, тариф, коэффициент, база, сверхлимит, спецнадбавка, НДС, след |
| Итог потребителя | прогон, потребитель, месяц, сумма точек |

Статус прогона:

- `готов` — обязательные ставки транспортировки есть, строки посчитаны;
- `незакрыт` — есть пробелы по ставкам транспортировки или обязательным полям, стоимости без ставки нет.

Повторное закрытие того же месяца заменяет его единственный прогон вместе со строками результата. Прогоны остальных месяцев не удаляются. Переходный тариф корректирует расчёт текущего месяца и следующих за ним. Уже закрытые предыдущие месяцы он не переписывает.

## Прогноз

В текущей архитектуре модуля прогноза нет. Позже объём до конца года будет считаться отдельным контуром с учётом сезонности, прогноза погоды и истории аналогичных периодов прошлых лет, а стоимость — тем же движком. Отдельный прогон прогноза и его история не закладываются, пока этого контура нет.

## Интерфейс

Окна вызывают сценарии прикладного слоя и показывают возвращённые таблицы. Общее состояние экрана — открытый файл базы, выбранные год и месяц, регион, группа, потребитель.

| Окно | Сценарий |
|---|---|
| Справочники | чтение и правка регионов, потребителей, точек, договоров |
| Тарифы | ставки транспортировки и спецнадбавки, подтверждение даты не с 1-го числа |
| Импорт | разбор файла, сопоставление колонок, предпросмотр, приёмка |
| Качество | журнал замечаний по загрузке и по прогону |
| Расчёт | готовность периода, запуск, таблица строк, карточка точки со следом |
| План-факт | агрегаты прогона по объёму и стоимости |
| Статистика | те же срезы: ставка, доля спецнадбавки, переходы, сверхлимит |

Фильтр региона, группы и потребителя применяется к уже посчитанным строкам. Население в этих таблицах отсутствует; журнал качества показывает, сколько таких строк отсечено при загрузке.

Длительный прогон выполняется вне потока интерфейса. Окно остаётся отзывчивым и по завершении перечитывает прогон.

## Сборка и проверка

Репозиторий на GitHub.

На pull request в `main` и на push в `main`:

- `task lint`;
- `task test`, включая эталоны `domain`: месяц смены группы, возмещение при повышении группы, сверхлимит и отказ считать население.

Сборка Windows-exe — на `windows-latest` через PyInstaller, артефактом сборки или релизом. На Mac разработчик запускает тот же пакет через интерпретатор и PySide6, без отдельной ветки кода. Docker на Mac может окружать разработку и тесты. В поставку для Windows он не входит.

Каталоги `domain`, `ingest` и `quality` покрываются тестами без окна и без файла базы. Сценарии прикладного слоя проверяются на временной SQLite. На Mac эти проверки можно гонять в Docker. Сборка для Windows остаётся без Docker.
